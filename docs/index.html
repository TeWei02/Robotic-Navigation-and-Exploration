Scope and status — please read before interpreting the demo

  • The interactive demo reproduces the deterministic pure-pursuit baseline (HW3-1/PathTracking/pure_pursuit.py), not a trained PPO policy. The trained checkpoint (HW3-1/save/model.pt) is not distributed with this repository, so no learned weights can be loaded here.
  • The recorded traces in data/reference.json are generated by tools/build_web_data.py from the repository's own simulator, and are tagged in the file itself with the same caveat (meta.note).
  • HW3-2 (Proly navigation) depends on an external macOS application and on the RL checkpoints produced during training; neither is included. Its reward function, curriculum launcher and evaluation scripts are readable in the repository, but they cannot be executed from a clean clone.
  • HW3-2/champion_stats.csv is a per-tick telemetry log written while a champion model played against that external application; it was recorded with an earlier revision of champion_play.py and cannot be regenerated here. It is raw telemetry, not a summarised experimental result.
  • Training numbers quoted anywhere in this page are those already recorded in the course report (HW3/report_4b4g0077.md and the PDFs), reproduced with attribution. They were not re-measured for this page, and no new measurements, subject counts or statistics have been invented.

Interactive path-tracking demo

Select an episode, then play it back. Six scenarios exercise the same controller under different regimes: nominal tracking, a high-curvature arc, an offset start pose that forces convergence, injected steering bias (off-path segments), and a saturated-turn recovery run that covers the negative branch of the progress reward.

What “replay” and “closed loop” mean

Replay feeds the steering commands stored by the Python run into the browser-side vehicle model. Since those commands are part of the published data set, the resulting trajectory, reward sequence and observation vectors can be compared element by element against the reference — the table on the right reports the worst deviation measured in this browser session.

Closed loop instead recomputes the steering command in the browser at every step from the current pose, using the same pure-pursuit definition (nearest path sample, arc-length look-ahead of 30 units, curvature κ = 2·sin(α)/Ld). Only the path and the start pose come from the data set, so this mode exercises controller, vehicle dynamics, reward and observation together.

Environment summary

ElementDefinition
Vehicle model Simulation/simulator_basic.py — constant forward speed (v = 0.6 · v_range = 12 units/s), steering command applied as a heading increment with a one-step lag, workspace 600 × 600, dt = 0.1 s. Bicycle and differential-drive variants are also implemented.
Action space One continuous steering-rate command in [−60, +60] deg/s.
Observation (14) Two previous poses (x, y, yaw — 6 values; x and y divided by 600, yaw converted to radians) followed by four future waypoints (8 values) spaced 16 path indices apart, starting at the nearest path sample (also divided by 600).
Reward 0.8·exp(−0.1·d²) + 0.2·exp(−0.1·Δψ²) + progress, where d² is the squared distance to the nearest path sample, Δψ the wrapped heading error in degrees against that sample’s heading, and progress ∈ {+0.1, 0, −1.0} rewards advancing along the path, ignores standing still and penalises moving backwards.
Termination Reaching the final path sample, or coming within the goal tolerance (10 units) of it, or exceeding the 400-step cap.
Controller used for the demo HW3-1/PathTracking/pure_pursuit.py — geometric look-ahead tracker, deterministic for a given path and start pose (no learning involved).

Reproduce locally

Everything on this page is generated from repository code; nothing is hand-authored data.

git clone https://github.com/TeWei02/Robotic-Navigation-and-Exploration
cd Robotic-Navigation-and-Exploration
python3 -m pip install -r requirements.txt

# rebuild and verify the published data set (compares against a live Python run)
python3 tools/build_web_data.py
python3 tools/build_web_data.py --check

# run the pure-pursuit baseline against the HW3-1 environment
python3 - <<'PY'
import numpy as np, sys
sys.path.insert(0, "HW3-1")
import wrapper
from PathTracking.pure_pursuit import PurePursuitController

np.random.seed(1)
env = wrapper.PathTrackingEnv()
ctrl = PurePursuitController(lookahead=30.0, v=12.0, w_range=60.0)
ctrl.set_path(env.path)

total = 0.0
for _ in range(400):
    _, w = ctrl.command(env.simulator.state.pose())
    _, reward, done, _ = env.step(np.array([w / 60.0]))
    total += reward
    if done:
        break
print("return =", round(total, 3))
PY

# tests (data set + determinism)
python3 -m pytest -q

# PPO training (PyTorch + GPU recommended; writes weight files that are not
# distributed with this repository)
cd HW3-1 && python3 train.py

Limitations

  • Only the HW3-1 path-tracking task is demonstrated interactively; HW3-2 cannot be reproduced without the external application.
  • The browser engine is a faithful port for the paths and controllers published here, but it is not a general-purpose simulator replacement — PPO training still runs in Python.
  • Reported training returns and scores are quoted from the course report; they were not re-run for this page.
